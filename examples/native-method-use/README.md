# Scoped contribution and permitted method use

This #1595 example exercises the existing native owners in two normally
registered projects within one disposable workspace. It answers a concrete
pre-installation question: does a new package **declare** support for the selected
Node/platform target? The task-owned `case-widget` manifests describe a controlled
case, not an observed customer incident. Nothing installs the package or tests
its live runtime compatibility.

Run from the repository with its supported toolchain and root/Apps dependencies:

```sh
node --import tsx scripts/test-native-method-use.ts /absolute/new/evidence-directory
```

The optional export directory must not exist. Without it, the regression still
runs and removes its disposable state. The existing integration suite registers
the same test. It uses the current process/resource lifecycle owners, generated
local authentication, production HTTP handlers and public MCP proxy entries.
It neither discovers nor changes the installed Companion. Network access is
limited to its owned loopback listener; no model, provider, payment or external
participant is involved.

## The actual chain

1. A's task asks whether `case-widget` 2.0 declares support for Node 22.23.4,
   Darwin and arm64. Source-bound authored terms distinguish an executor's direct
   restriction from A's separately permitted commissioning. Project-wide and
   requester-specific no-commissioning contrasts save `Wait`; the allowed case
   saves `Commission`. These choices are authored, not policy inference.
2. The execution-choice/manual-contribution preparation pins the selected input
   bytes and complete `operating-profile.json` step through ordinary preview/save.
   `expected_return` is the report. Hypothetical B benefit, beneficiary, condition,
   proposal, authored acceptance and unfulfilled status remain separate terms.
3. `check-declarations.mjs` actually compares the requested manifests. The
   baseline fits; the candidate's Node requirement does not. Its full report
   includes an explicitly unsupported installation suggestion. A preserves the
   exact original and saves a checked `partly_used` judgment plus a useful hold
   recommendation. Report acceptance, partial use and compensation remain distinct.
4. The source project stores B's task-owned private checklist separately and
   publishes only the original report and a derived conditional procedure. The
   shared method carries source/version, supported syntax, applicability,
   contrary case, limitations and correction instructions. An explicit target
   share and a consumer-owned corpus use `put_material` and `publish`, with
   `envelopes: []`. No task-local source binding is copied into C's source list.
5. A new C process receives only its registered project entry. It reads the saved
   task and corpus through ordinary readers, retrieves permitted whole groups,
   checks original bytes, current binding and its own authored authority, then
   runs the procedure against version 2.1 on Node 24.22.1. It persists a checked
   artifact and its own `adapt` judgment. Expected outcomes live only in the
   parent evaluator; C never reads A's saved answer or evaluator files.
6. Fresh processes repeat with only a display-label change (identical checked
   output) and a request for live-runtime evidence (useful `non_use` judgment).
   A correction makes the earlier binding stale; fresh inspection exposes it.
   Withheld/undeclared material and transplanted source IDs refuse. Withdrawal
   stops new shared reads while prior delivered copies and C outputs remain
   readable. Missing authentication and stale runtime generation also refuse.

## Intent to owner to evidence

| Intent | Actual owner | Exported evidence and limit |
| --- | --- | --- |
| Restriction scope and separate terms | Ordinary revision writer; `execution-choice.mjs` | `scope-controls.json`, `contract.json`: structurally preserved authored choices; no policy or settlement enforcement. |
| Profile step and bounded request | `operating-profile.mjs`, `manual-contribution.mjs`, ordinary preview/save | `profile-preview.json`, `request.json`: complete pinned profile; `execution_ready: false`, permissions/principals/budget remain declarations. |
| Original return, checking and partial use | Manual contribution receive/read/assess and ordinary source writer | `original-report.json`, `a-output.json`, `a-saved.json`: negative finding, exact original and useful downstream result; authored acceptance. |
| Permitted cross-project method | `external-response.ts`, external store and current share/configuration checks | `derived-method.json`, `producer.json`, `boundaries.json`: explicit share, immutable materials, exact replay, withheld/withdrawn refusal. |
| Fresh current use and unsuitable non-use | `selected-source-use.mjs`, production corpus/retrieval owners, ordinary work/source writers | `consumer-*-delivery.json`, `consumer-*-output.json`, `consumer-*-judgment.json`, `consumer-*-saved.json`: three fresh processes; current C task identity and source-bound result. |
| Currentness, authentication and recovery validation | Private external HTTP route, snapshot/preview/save and external-store validator | Stage traces, `current-correction-read.json`, `boundaries.json`: actual refusals and valid retained store, without restoring withdrawn sharing. |
| Finite lifecycle and burden | Existing canonical child/resource owners | `stage-results.json`, `*-settlement.json`, `report.json`: actual duration, calls/bytes in traces, natural exit and no owned processes; human preparation/model usage unmeasured. |

The checker supports only `>=major.minor.patch <major` and positive literal
`os`/`cpu` arrays. It is not a general semver implementation. A hash, successful
schema check or matching declaration proves neither installation nor ABI,
dependency or live-runtime compatibility. A's Node 22 target is supplied data;
the script's host Node version is separately recorded by verification.

## Retain the existing composition

No product contract violation was needed to complete this path. Retain the
current writers, small note/material budgets, permission checks and explicit
before-use recheck. The example adds no Core type, database migration, dispatcher,
capability registry, allocator or payment ledger. Policy interpretation, method
derivation/applicability and compensation acceptance remain attributed authoring.
Automatic paid commissioning/settlement and independent cross-owner operation
are unimplemented relationships, not hidden fixture capabilities.

Use ordinary notes for these bounded terms and judgments until a concrete
producer/consumer needs enforced semantics; do not promote the example's JSON
shapes into protocol. C's static check is controlled cross-project reuse, not
independent participation, autonomous method discovery, a strong comparison or
evidence of reduced total burden. No UI, production access, installed state or
#1594 Web reassessment owner changes. Removing these examples/tests rolls back
the increment; no persisted format downgrade is required.
