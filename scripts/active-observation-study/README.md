# Chosen observations and actual file work (#1464)

This is a disposable research prototype, not a Web/Core/Companion feature.
It connects conditional experience, a next-action procedure, selected execution,
feedback, checked files and a fresh later consumer. Run the complete model-free
regression path from the repository:

```sh
node scripts/test-active-observation-study.mjs
```

The test uses the existing resource/process owners, writes real input/result and
report files, and removes its owned resources. The native study retains the
original permitted output bytes separately. The normal complete unit suite also
runs this test; neither the research label nor its registration narrows the
unchanged Local Canonical plan.

## Task and supplied mechanics

The first task finishes an interrupted settlement: three file obligations,
including two already-issued fast operations, within 20 **simulated task-cost
units**. The later task is a new recurring regional allocation: six new inputs,
no inherited operations or scalar results, two group limits and a 30-unit budget.
It requires every per-file result and regional subtotal/limit conclusion. A
fresh process alone is not the difference between these tasks.

Each input is a small JSON array of integer `cents` and nonnegative `units`;
the output is the sum of their products. UTF-8 and BOM-tagged UTF-16LE files are
valid. Initial encoding metadata is a checked byte property, not a compatibility
answer. The input bytes and environment implementation stay outside the native
consumer material. A source fingerprint binds experience to the actual tool.

The supplied interface has `fast` (2 units), `robust` (6), `diagnose` (3),
`status` (1), `wait` (1–16), and `finish` (1). View reads are free but reveal
only prior observations. Productive actions can run while prior work is pending.
A supported fast operation finishes at issue+4 and becomes available on the
delivery path at issue+6; unsupported/invalid fast work finishes at issue+2 and
becomes available at issue+8. Diagnosis reads execution state after its cost;
status reads delivery state. Robust processing finishes after its 6-unit cost.
Waiting advances the declared clock without inventing an observation. The actual
output bytes are produced by execution; these delays are simulated, never claimed
as measured service latency. No background process, external service or noise is
needed. This deterministic domain does not warrant calibrated probabilities.

Possible compatibility hypotheses, action mechanics/costs, timing, the encoding
condition language, selection policy, arithmetic, identity and checks are supplied
scaffolding. The initial model has **no observed compatibility conditions**.
`method.mjs` deterministically learns supported/unsupported fast conditions only
from actual terminal observations. It preserves observation identity and times;
pending, invalid and unknown results do not establish compatibility. A conflict
keeps both outcomes and returns unknown; changed tool scope does not inherit a
rule. Diagnosis and later actual use establish the bounded condition-learning
mechanism; an LLM does not rediscover this updater or arithmetic.

Candidate selection compares explicit action alternatives/costs under the current
conditional model. `reference.mjs` is ordinary adaptive memo/code with the same
updater and tools. It prioritizes productive work, reconciles outstanding work,
and revises the processing route after feedback. Both may be inspected and
revised by their assigned native consumer; the reference may also reuse candidate
utilities. Neither arm receives selected observations or correct action traces.

## Consumer entry and retained use

A task-owned consumer directory contains `work.mjs`, `method.mjs`,
`reference.mjs`, a connection to its own disposable environment, and the contract.
The normal local command path is:

```sh
node work.mjs view candidate
node work.mjs suggest candidate
node work.mjs act candidate '{"action":"diagnose","work_id":"example"}'
node work.mjs run candidate
```

Use `reference` for the ordinary initial policy. `act` makes one selected action;
`run` executes the selected method until completion or its finite budget. Neither
entry creates a model process. The included native client, when separately
authorized, chooses/invokes/revises this ordinary executable. Every action binds
its pre-action public view, model and method hashes. Output versions keep before
and after models and observed results; `results.json` and `report.json` contain
the actual result identities and totals, with a readable `report.md`.

A fresh later consumer receives its own arm's exact retained code, model and
permitted observations, plus the new contract. Its `start.json` binds the loaded
model and method. It must actually run the retained method and generate new
files. Earlier chat, the other arm, environment truth and evaluator answers are
excluded. This is protocol isolation on a shared-user filesystem, not hostile
OS isolation. Inspect observed access before making any exposure claim.

## Correctness and fixed comparison

Pending does not authorize reissue: an unreconciled operation refuses a possibly
duplicating action. Repeated status delivery retains the event ID and counts
once as experience. Different work IDs remain different even with equal values.
Later availability never changes an earlier pending record. Incomplete groups
keep an unknown limit result. The independent checker uses separate BigInt
arithmetic and checks the original event bytes, identity, coverage and budgets;
it does not rescue a bad action or provide observations to a consumer.

Freeze environment source/inputs, task contracts, initial methods, online update
rules, prompts/order, tool settings, costs, checks and stop rules before fixed
observation. Learned state may evolve; consumer code/memos may be revised only
from its own actual permitted feedback, with every version preserved. No
coordinator repair, coaching, replacement or outcome-selected rerun belongs to
that comparison. Match initial resources, not acquired histories: selection is
the intervention. Development fixtures were exposed to the common author and
tests; this small constructed study is not blind, independent demand or a
general superiority result.

Keep task costs, action/diagnostic counts, correct completion, wasted work,
acquisition and later use, actual process time, model usage and human/coordinator
assistance distinct. A tie or greater total burden supports simplifying to the
ordinary reference. Source qualification and a native successful output are
separate evidence. Preserve all failed slots and unknown internal costs. The
single assignment's allocation/receipts/report live with its delivery; this
README grants no future model, publication or production authority.
