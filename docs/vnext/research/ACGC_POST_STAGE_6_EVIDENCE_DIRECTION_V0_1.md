## 2. Why this consolidation exists

Recent design proposals examined trajectory governance, reference-conditioned
deviation, compositional control, long-term-memory reconstructability,
relational functional identity, relational continuity, bounded re-entry
perturbation/reset, and anomaly-preserving reconstructable memory.

They should not become eight independent subsystem families. Their strongest
claims converge on one evidence-first extension of ACGC:

```text
exact provenance and authority
→ rebuildable observation
→ explicit contrast/reference
→ bounded intervention and outcome attribution
→ component-level composition evidence
→ separate governance decision
```

The objective is not to add more memory, agents, graphs, monitors, or policy
objects. It is to improve what Augnes can truthfully establish about how prior
state, evidence, references, strategies, and unresolved anomalies affect later
work while preserving existing authority boundaries.

## 3. Current evidence boundary after Stage 6

The Stage 5 exact continuation case established that:

- the continuation mechanism worked end to end;
- one selected operational entry was delivered and exactly referenced;
- item actual use remained unknown;
- support validation remained unknown;
- outcome association remained unknown;
- causal contribution remained unknown;
- task and verification results were equal in the deciding exact case;
- observed structural coordination and complete-path review burden favored the
  one-run baseline;
- material usage, monetary cost, required human intervention, and genuine
  performance latency remained unobserved; and
- the exact-case conclusion remained `inconclusive`.

ACGC6A then established bounded route-contract and fallback readiness across
deterministic model/host profiles without establishing model quality, route
superiority, policy fitness, or automatic-fallback authority.

ACGC6B therefore selected **no live operational policy** for the current
evidence state. That no-policy decision remains the governing architecture
choice after Stage 6 completion.

The most important remaining research gap is not mechanism availability. It is
whether selected prior material actually changes later structured computation
in a supportable way, whether that change improves outcomes, and whether the
system can relinquish stale or harmful continuity when the evidence regime
changes.

## 4. Preferred post-Stage-6 evidence order

The following order is a **research preference**, not an authorized phase
sequence.

### 4.1 Matched re-entry perturbation and reset

Highest information-value candidate for a separately authorized next research
slice.

Distinguish the evidence ladder explicitly:

```text
Availability
→ Reference
→ Conditioning
→ Support
→ Outcome Association
→ Causal Contribution
```

No step implies the next one.

A minimum research comparison should preserve parity and compare:

```text
A. exact re-entry
B. matched ablation of one selected item
C. stale / regime-shift substitution or refusal case
D. existing one-run baseline
```

The initial success criterion is not that continuation wins. It is that Augnes
can distinguish delivery, reference, structured downstream conditioning,
support, outcome relation, intervention sensitivity, and reset behavior without
inventing missing evidence.

Reset is first-class. Useful continuity must be able both to condition future
work and to stop reinforcing prior state when source currentness, contradictory
evidence, or semantic regime changes invalidate it.

### 4.2 Reconstructability conformance

Run a separate low-authority architecture test for rebuildable derived state.

Two different tests must not be collapsed:

#### Projection rebuild conformance

```text
same exact sources
+ same rule version
→ same normalized derived output
→ same fingerprint
```

This tests deterministic implementation, source completeness, decision-time
cutoff, zero unauthorized effects, and rebuildability.

#### Semantic reconstruction perturbation

```text
derived summary / digest / prior packet representation removed
→ canonical evidence + Decision / Transition lineage
→ project-relevant semantic relations reconstructed
```

This does **not** require identical text, token order, embedding, explanation,
or presentation. It tests recovery of accepted state, provenance, scope,
currentness, contradiction, unresolved questions, constraints, uncertainty,
and authority boundaries.

Therefore:

```text
Projection Rebuild Conformance
≠ Semantic Reconstruction Perturbation
```

Candidate knowledge may be reconstructed or transferred. Capability grants,
execution authorization, approvals, and irreversible-operation authority must
be freshly resolved at the current boundary.

### 4.3 Trajectory gap audit and phenotype casebook

Before adding a runtime monitor, new event schema, or learned classifier, audit
what the current records can already establish about within-run and cross-run
trajectory structure.

The first two hypotheses worth testing are:

#### H1 — Global leverage stall

```text
local valid activity increases
while
progress against the original success criterion repeatedly stalls
```

Local activity may include more decomposition, files, analyses, lemmas,
verification plans, or candidate strategies. None is itself proof of global
criterion leverage.

#### H2 — Authority reclassification drift

```text
hard constraint correctly recognized
→ repeated operational pressure / precedent / task-completion pressure
→ constraint treated as an obstacle or feasibility variable
→ observable plan/action relation changes
```

The casebook should preserve positive controls as well as negative candidates.
It must describe observable lineage only and must not infer hidden intent,
private chain of thought, reward hacking, or an internal objective.

Only if the gap audit proves that current source records cannot represent a
repeatedly useful relation should a minimal new read-only event/projection
contract be considered.

### 4.4 Reference-conditioned deviation

A deviation has meaning only relative to the reference against which it was
computed.

The first research vocabulary may distinguish references such as:

```text
immediate_prior
last_applied_transition
explicit_expectation
contrastive_precedent
unresolved_residual
```

Reference choice is not neutral preprocessing. A selector or model must not be
able to choose a favorable historical baseline and then treat the resulting
deviation as objective truth.

Keep these distinctions:

```text
Reference Candidate ≠ Admitted Reference
Admitted Reference ≠ Used Reference
Model-Selected Baseline ≠ Trusted Baseline
Difference ≠ Prediction Error
Prediction Error ≠ Anomaly
Deviation Magnitude ≠ Authority
```

`ContinuityDynamics` and reference-conditioned deviation have different
responsibilities:

```text
ContinuityDynamics
= how a bounded recent work-state sequence is moving

Reference-Conditioned Deviation
= how a current observation relates to an explicit reference basis
```

Do not widen `ContinuityDynamics` merely to avoid naming this distinction.
However, do not add a new durable deviation owner until repeated source-gap and
consumer evidence justifies it. Casebook/report vocabulary is preferred first.

### 4.5 Anomaly-retention diagnostics

An unresolved anomaly should not become truth merely because it is retained,
and it should not disappear merely because it was not selected or accepted.

Preserve:

```text
not accepted ≠ erased
not selected ≠ disproven
deferred ≠ forgotten
rejected hypothesis ≠ deletion of its supporting anomaly
superseded ≠ provenance destruction
```

Initial anomaly retention should be rebuilt from existing sources such as
conflicts, missing information, uncertainty, defer/rejection reasons, revisit
conditions, supersession, contradiction, and recurring blocker evidence.

Do not create an `AnomalyLedger`, anomaly database, activation score, or new
source of truth before an actual reconstruction/retrieval failure proves the
need.

Repeated restatements derived from one original source must not be counted as
independent corroboration. Distinguish independent origins from same-source
derivatives before using recurrence as evidence.

### 4.6 Bounded composition intervention

Existing strategy-composition machinery should be reused. Do not add a new
controller runtime merely because multiple functional components are useful.

The first important question is:

> Does a bounded multi-component composition outperform the strongest
> equal-budget single component on downstream outcomes?

Compare, where applicable:

```text
base only
each single bounded component
current bounded multi-component profile
composition review
ordinary critique baseline
zero-model fallback
```

Evaluate component contribution, complementarity, redundancy, interference,
conflict, negative transfer, later outcome, review burden, and resource cost.

```text
co-selection ≠ complementarity
co-occurrence ≠ causal contribution
helpful bundle outcome ≠ credit for every component
```

Internal composition may remain soft and plural. External commitment remains
explicit and hard:

```text
Soft internal composition.
Hard external commitment.
```

No component mixture, weight, agreement, or composition result creates truth,
Decision, Transition, grant, or execution authority.

### 4.7 Relational functional profile only after intervention evidence

Do not begin by declaring a persistent actor and then infer its function from
its name.

Preferred evidence order:

```text
bounded reusable components
→ repeated episode observation
→ relational bundle candidate
→ task-exclusion / confound checks
→ held-out selectivity
→ controlled remove / replace / rebind / reorder / withhold intervention
→ reusable functional-bundle candidate
→ only if needed, later actor-reification decision
```

Preserve:

```text
DeclaredActorSpec ≠ ObservedFunctionalProfile
ObservedFunctionalProfile ≠ GrantedAuthority
Functional Stability ≠ Persistent Actor Identity
Persistent Actor Identity ≠ Authority
```

A future relational profile should consume existing ACGC composition,
attribution, review, outcome, and model/host-succession evidence rather than
creating a second graph or memory platform.

### 4.8 Separate governance decision

Stage 7, live operational policy, persistent actor, automatic winner promotion,
and population evolution remain separate decisions after evidence collection.

Research output may support a later decision packet. It may not activate the
thing it evaluates.

## 5. Exact integrity and relational continuity

Cross-model and cross-session continuity should not require identical hidden
state or identical wording.

Keep two evaluation classes separate.

### 5.1 Exact integrity continuity

Exact equality or exact lineage is required for governance-bearing material:

- workspace/project/work identity;
- source IDs and fingerprints;
- decision-time cutoff;
- scope and currentness;
- candidate/accepted/rejected/superseded status;
- required checks and forbidden effects;
- grant scope and authority source;
- predecessor/fallback chronology where owned;
- `ReviewDecision` versus applied `StateTransitionReceipt` identity.

### 5.2 Relational semantic continuity

Surface expression may vary while decision-relevant relations remain intact:

- which source supports or opposes a claim;
- which constraint blocks which action;
- what remains unresolved;
- which uncertainty requires further verification;
- which candidate is not yet accepted;
- which check was not actually performed;
- which minority or conflicting lineage remains unfalsified.

The external Augnes contract is the shared cross-model space. Do not depend on
provider hidden-state alignment, a shared embedding manifold, or a global
`continuity_score` to establish continuity.

Useful negative fixtures should include semantic-near but authority-far pairs:

```text
candidate knowledge / accepted knowledge
reference / support validation
ReviewDecision / StateTransition
predecessor grant / fresh successor grant
fallback available / fallback activated
execution completed / criterion verified
minority Perspective / falsified Perspective
```

## 6. Common epistemic and authority invariants

The post-Stage-6 research direction preserves all current ACGC firewalls and
adds no automatic authority.

```text
Observation ≠ Evidence
Evidence ≠ Proposal
Proposal ≠ Decision
Decision ≠ Transition

Selected ≠ Presented
Presented ≠ Referenced
Referenced ≠ Actually Used
Actual Use ≠ Support
Support ≠ Outcome Association
Outcome Association ≠ Causal Contribution

Local Progress ≠ Global Leverage
Peer Precedent ≠ Capability Grant
Constraint Recognition ≠ Constraint Preservation
Trajectory Association ≠ Causal Mechanism

Deviation ≠ Anomaly
Anomaly ≠ Importance
Anomaly Retention ≠ Semantic Acceptance

Functional Stability ≠ Actor Identity
Actor Identity ≠ Authority
Policy Fitness ≠ Policy Activation
Knowledge Continuity ≠ Grant Continuity

Monitor Consensus ≠ ReviewDecision
Statistical Normality ≠ Authorization
OOD ≠ Unsafe
Proof ≠ Approval
```

Missing evidence remains `unknown`. A convenient narrative must not convert
missingness into a negative fact or a success claim.

Hard failures are not compensated by unrelated benefits. Harmful transfer,
verification regression, authority leakage, wrong-context increase,
stale-context persistence, source-lineage breakage, or project-scope leakage
remain explicit non-compensable lanes.

## 7. Architecture admission rule

Naming a concept in research is not a reason to reserve durable architecture
for it.

Do not add a new persisted type, schema, migration, owner, database, graph,
memory platform, policy pointer, or default product surface unless all of the
following are demonstrated:

1. a repeated real failure or source-observability gap exists;
2. the existing owner cannot represent it truthfully;
3. at least one concrete repeated consumer exists;
4. deterministic validation/rebuild semantics exist where applicable;
5. missingness and stale/current boundaries are explicit;
6. persistence, if proposed, has deletion, migration, backup/restore,
   portability, and rollback meaning;
7. no product, protocol, semantic, execution, external-effect, or merge
   authority owner is duplicated or widened; and
8. the narrower fixture/casebook/read-only-report alternative is insufficient.

Until those conditions hold, prefer:

```text
fixture
→ casebook
→ pure report
→ rebuildable read-only diagnostic
→ only then contract/persistence review if justified
```

gap. Reconstructability conformance and the trajectory casebook are valuable
parallel low-authority evidence, but neither should be mistaken for proof that
continuation improves work.

## 9. Stage 7 re-entry evidence diet

The existing ACGC6B no-policy decision remains unchanged. Stage 7 should not be
reopened merely because richer diagnostics can be designed.

A later re-entry review should have evidence across the relevant lanes rather
than one aggregate score, including where applicable:

- repeated bounded benefit across independent cases;
- matched intervention sensitivity;
- stale/regime-shift reset sensitivity;
- harmful-transfer and wrong-context behavior;
- verification and hard-gate integrity;
- task-family holdout;
- model/checkpoint and host transfer;
- source-independence and derivation audit;
- usage, cost, wall-clock latency, coordination, and human-review burden;
- OOD and disagreement behavior for any later monitor family; and
- evidence that the current explicit path has an actual recurring failure that
  a narrower read-only approach cannot solve.

A missing resource lane is not zero cost. A successful single case is not
repeated benefit. A working mechanism is not policy fitness.

## 10. Explicit non-goals

This direction does not authorize or require:

- a new Core record family;
- a new canonical memory object or memory platform;
- a graph database or general relation ontology;
- a durable `ReferenceSet`, `DeviationObservation`, `AnomalyLedger`, or
  `ObservedRelationalProfile` owner now;
- provider hidden-state or chain-of-thought storage;
- shared embedding/manifold alignment;
- a scalar surprise, anomaly, continuity, actor-fitness, or project-health
  score;
- automatic context injection;
- automatic Packet C or a second continuation hop;
- automatic fallback or rollback;
- automatic Start or Resume;
- active operational-policy state or pointer;
- persistent actor productization;
- actor-private product memory;
- automatic winner, actor, strategy, or lineage promotion;
- evolutionary population selection;
- C9, Linux rollout, remote nodes, long-horizon control, continuous policy, or
  multi-agent orchestration;
- product UI, dashboard, navigation, card, badge, or default concept merely to
  expose a research diagnostic.
